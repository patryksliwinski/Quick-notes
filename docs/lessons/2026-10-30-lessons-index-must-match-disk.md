# 2026-10-30 — The lessons index must match disk: never merge a `docs/lessons/` change without re-syncing `README.md` (issue #73)
- **Context:** PR #67 consolidated the lessons log (35 files → 27: 4 merged into new files, 12 folded) but only partially updated `docs/lessons/README.md`. On `main` after the merge the index had 12 rows linking to deleted files — including a release row still claiming "(unsigned for now)" even though signing had landed — and 4 newly created files were not indexed at all. Nothing caught it: the automated review in `pr.yml` only printed "docs/lessons/ updated" without checking that the index and disk agree.
- **Lesson:** Renaming, deleting, or adding lesson files and updating the index are one atomic change, not two steps that can drift. A link checker is cheap and deterministic — every `docs/lessons/*.md` file linked exactly once from the index, no index row pointing at a missing file — so enforce it in CI instead of relying on reviewer diligence. Stale index rows are worse than no rows: they actively mislead (here, a reader would conclude releases are still unsigned).
- **Rule now:** `.github/workflows/pr.yml` has a `lessons-index` job that runs on PRs and fails when the index and `docs/lessons/` on disk disagree (dead links, unindexed files, duplicate links). `docs/lessons/README.md` "How to add a lesson" and `docs/WORKFLOW.md` state the index-must-match-disk rule, and the PR template asks for it explicitly. Fix verified on `main` after this PR: 0 dead links, 0 unindexed files, 0 duplicates, and the "(unsigned for now)" row replaced by the signed-release-pipeline lesson.
