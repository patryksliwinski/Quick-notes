# 2026-10-29 — SAF I/O failures must never crash the app

- **Context:** Issue #16 — after switching the storage folder to a micro SD card (SAF `ACTION_OPEN_DOCUMENT_TREE`), tapping `+` killed the process. `SafNoteStore.createWithName()` threw `IllegalStateException` when `DocumentsContract.createDocument()` returned null (card removed / permission lost), and neither `NoteRepository.createNote()` nor `NotesViewModel.createNote()` handled it, so the uncaught exception in `viewModelScope` killed the process.
- **Lesson:** Every `NoteStore` call can fail at runtime on a removable SAF folder, and an uncaught exception in a coroutine kills the whole process. The repository must wrap all store calls, surface failures as state (`NoteError` flow → snackbar), and fall back to app-private storage when the SAF folder becomes unwritable — per the AGENTS.md rule "I/O failures surface as a snackbar/banner, never a crash". Also, `takePersistableUriPermission` can throw `SecurityException`; swallowing it silently left the app in a state where the SAF store was selected but writes failed — the picker must check the persisted grant and report it.
- **Rule now:** `NoteRepository` wraps every store operation in try/catch, exposes `errorMessage: StateFlow<NoteError?>` consumed by the list screen as a snackbar, and `recover()` falls back to `InternalNoteStore` (setting `folderRevoked`) when the SAF store fails. `createNote()` returns `NoteMeta?` so callers only navigate to the editor on success. `FolderPrefs.takePermission()` returns `Boolean`; `SettingsScreen` reports `FolderPermissionLost` when the grant was not persisted. Covered by unit tests with a `FailingNoteStore` fixture (SAF paths remain excluded from the Kover gate as device-only).
