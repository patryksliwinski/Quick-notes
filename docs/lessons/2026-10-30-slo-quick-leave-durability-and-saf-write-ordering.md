# 2026-10-30 — SLO "open < 1s, type, leave < 100ms": journal pending saves, never delete-before-rename on SAF, dedupe cold-start scan (issue #30)

- **Context:** Issue #30 audited the quick path against the SLO and found three gaps: (1) a process kill inside the 400 ms autosave debounce lost the last keystrokes because nothing durable tracked unsaved content; (2) `SafNoteStore.writeText()` deleted the original document *before* renaming the tmp file into place, so a kill in between destroyed the note; (3) cold start ran two concurrent `listNotes()` scans (`NotesListScreen.LaunchedEffect` + `MainActivity.onResume`).
- **Lesson:** "Leave < 100 ms" can only mean UI-leave latency; durability on quick leave must be asynchronous. Every `writeNote` first journals `(uri, content)` in a dedicated SharedPreferences file (`PendingSaveJournal`) and clears the entry only after the store write succeeds; on cold start `MainActivity` → `flushPendingSaves()` rewrites whatever is still journaled, so a kill during the debounce window is recovered on next launch. SAF writes never delete before the rename commits: the original is renamed to a dotfile `.bak`, the tmp is renamed to the target name, and only then is the `.bak` deleted; if the commit rename fails the `.bak` is renamed back. AOSP's `FileSystemProvider.renameDocument` does not overwrite on name conflict (it picks a unique name), so plain rename-over is not portable across providers. Leftover `.tmp`/`.bak` dotfiles from a kill are healed on the next `listNotes()` scan (bak restored if the note is gone, tmp/bak deleted otherwise) — dotfiles were already ignored by the list, so this adds no visible artifacts. Cold-start refresh is deduped by coalescing concurrent in-flight refreshes in `NotesViewModel.refresh()` (skip while a refresh job is active), which fixes the double scan without adding a time-based skip that could swallow legitimate `onResume` resyncs.
- **Rule now:** Pending saves are journaled before the storage write and flushed on cold start (`PendingSaveJournal` + `NoteRepository.flushPendingSaves`, triggered from `MainActivity.onCreate`). SAF and internal writes commit via tmp→rename with a `.bak` rollback; interrupted writes leave only dotfiles, healed on the next scan. One refresh in flight at a time per `NotesViewModel`. Documented in `docs/ARCHITECTURE.md`.
