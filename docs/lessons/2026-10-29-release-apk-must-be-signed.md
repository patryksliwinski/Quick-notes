# 2026-10-29 — Release APK must be signed or Android rejects it ("package appears to be corrupt")

- **Context:** v1.0.0 published `app-release-unsigned.apk`; installing on a Samsung S20 FE failed with "couldn't install because the package appears to be corrupt" — the APK contained no `META-INF/*.SF|RSA|DSA` signature block at all, which Android's package installer rejects outright.
- **Lesson:** `assembleRelease` without a `signingConfig` emits an unsigned APK; it can never install on a device. Signing is not optional for distribution. The simplest zero-config approach for a single-user app is an ephemeral keystore generated in CI (`keytool -genkeypair`) + `apksigner sign`/`verify` from the already-installed `build-tools;35.0.0`, with no repository secrets to manage. Trade-off: each release is signed with a different key, so a later release cannot be installed as an in-place update over an earlier one — the old APK must be uninstalled first (fine for a personal app; a stored keystore secret is the fix if that ever matters).
- **Rule now:** `release.yml` signs `app-release-unsigned.apk` into `app-release.apk` and publishes only the signed APK; the pipelines table in `docs/WORKFLOW.md` reflects this.
