# 2026-10-30 — Widget rows must not rely on `0dp`+`layout_weight` when sibling rows are GONE
- **Context:** issue #34 — after the resizable-widget change, the recent-notes widget showed only its header: note content (title/snippet) was invisible. The in-app list had the same symptom whenever the index fell back to filename/empty snippet.
- **Lesson:** in a vertical `LinearLayout` rendered through `RemoteViews`, children with `layout_height="0dp" + layout_weight="1"` only get the space left after `wrap_content` children; rows hidden with `setViewVisibility(GONE)` can still participate in weight distribution on some launcher hosts, collapsing the visible rows to zero height so their `TextView`s render nothing. Row containers must stay `wrap_content`, hidden rows must be GONE **and** have their text cleared, and every row slot must always be bound. Also, `OPTION_APPWIDGET_MAX_HEIGHT` is the current portrait height but some hosts report the other bound in `MIN_HEIGHT`, so read both (`widgetHeightDp`).
- **Rule now:** widget row containers use `wrap_content` (never `0dp`+weight next to GONE siblings); the provider always binds text for all row slots and clears text on hidden rows; widget height is read via `widgetHeightDp(options, fallback)`; all disk/SAF loading stays off the main thread (`goAsync` + `Dispatchers.IO`, one load per update — no per-keystroke rescans).
