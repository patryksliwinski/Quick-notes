# 2026-10-29/30 — SAF failure modes: never crash, never silently return empty (issues #16, #23 follow-ups)
- **Context:** Three distinct SAF failure modes, each with a different wrong fix: (1) issue #16 — tapping `+` crashed the process because `SafNoteStore.createWithName()` threw when `createDocument()` returned null (card removed / permission lost) and no layer caught it; (2) the folder picker swallowed a `SecurityException` from `takePersistableUriPermission`, leaving the SAF store selected with writes failing; (3) issue #23 — creates on SD cards silently fell back to app-private storage because `createDocument` was given the tree URI instead of the document URI (`buildDocumentUriUsingTree(tree, getTreeDocumentId(tree))`); removable volumes reject the tree URI. Separately, a stored tree URI alone is not enough — the OS can revoke persisted permissions, so `persistedUriPermissions` must be checked for write access.
- **Lesson:** On removable SAF storage, every store call can fail at runtime, and an uncaught exception in a coroutine kills the whole process. The repository must wrap all store calls, surface failures as state (`NoteError` flow → snackbar), and fall back to app-private storage when the folder becomes unwritable; the picker must verify the persisted grant and report `FolderPermissionLost`. SAF `createDocument` needs the tree's **document URI**, never the raw tree URI, and `uri.lastPathSegment` is the encoded document ID, not the display name — resolve names via `COLUMN_DISPLAY_NAME` before renaming. And a storage layer must never convert an unavailable volume into empty content: null cursors/streams are errors and must throw, because `""` is indistinguishable from a real empty note and gets autosaved over the file (see `2026-10-30-journal-record-must-commit-saf-failures-must-throw.md`).
- **Rule now:** `NoteRepository` wraps every store operation in try/catch and exposes `errorMessage: StateFlow<NoteError?>`; `recover()` falls back to `InternalNoteStore` (setting `folderRevoked`); `createNote()` returns `NoteMeta?`; `FolderPrefs.hasPersistedPermission` gates store resolution; `SafNoteStore` derives `parentDocumentUri` once via `parentDocumentUriOf(treeUri)`. Encoded in AGENTS.md error-handling rule and `docs/ARCHITECTURE.md`. Covered by `FailingNoteStore` fixture tests; SAF paths stay device-only per the Kover exclusions.
