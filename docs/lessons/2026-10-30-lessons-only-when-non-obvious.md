# 2026-10-30 — Lessons are required only when non-obvious, not on every PR
- **Context:** Issue #50 — the workflow required a `docs/lessons/` entry in every PR (pr-review warning + PR-template checkbox). In ~2 days this produced ~30 lesson files, many with no novel lesson, added only to tick the box and silence the warning.
- **Lesson:** When a rule requires an artifact every time, the artifact becomes noise and the genuinely valuable lessons get buried. A high-signal log beats a complete one.
- **Rule now:** Add a `docs/lessons/` file **only if** the PR taught something non-obvious (perf trap, API gotcha, CI failure, a decision you'd make differently). The `automated-review` job in `pr.yml` now says exactly that (ℹ️, not ⚠️) instead of warning on every PR without one (historically this scan lived in the since-deleted `pr-review.yml`); the PR template, `AGENTS.md`, `CONTRIBUTING.md`, `docs/WORKFLOW.md`, and this index all state the conditional rule. Exception: a PR that changes a rule in `AGENTS.md` / `docs/WORKFLOW.md` always gets a lesson explaining why. Recurring lessons are still folded into `AGENTS.md` periodically — that's where the value compounds.
