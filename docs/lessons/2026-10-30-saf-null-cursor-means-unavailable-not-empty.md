# 2026-10-30 — A null SAF cursor/stream means "volume unavailable", never "empty folder" (issue #59)

- **Context:** Issue #59 — notes stored in an SD-card (SAF) folder did not show in the main list. `SafNoteStore.listNotes()` did `resolver.query(childrenUri, ...)?.use { ... }`, so a null cursor (volume not yet mounted at cold start, transient provider failure) returned an empty list with no exception; `NoteRepository.refresh` then treated the folder as empty and showed "no notes" while the files were on the card. Same silent-empty pattern in `healOrphanedSafDocuments` (null cursor → no healing) and `readNote`/`readHead` (null stream → `""`). Additionally, AOSP's `FileSystemProvider` only publishes `COLUMN_LAST_MODIFIED` when it is > 1 year after epoch; older/missing values read back as `0`, which sorted those notes to the bottom under a 1970-01-01 day header, making them look "missing".
- **Lesson:** In SAF code, a null `Cursor` from `resolver.query()` or a null stream from `openInputStream()` is an error signal, not an empty result — only a non-null cursor with zero rows means "empty folder". Throwing makes `NoteRepository.refresh` fall back to app-private storage, set `folderRevoked` + the `FolderUnavailable` banner, and keep the last known list instead of blanking it. Sanitize non-positive `COLUMN_LAST_MODIFIED` to "now" so those notes stay visible and sort normally. Robolectric can fake this with a registered `ContentProvider` returning a null cursor (no device needed).
- **Rule now:** `SafNoteStore.listNotes`/`healOrphanedSafDocuments`/`readNote`/`readHead` throw `IOException` on a null cursor/stream; `listNotes` maps `COLUMN_LAST_MODIFIED <= 0` through `safLastModified()`; `NoteRepository.refresh` keeps the last known `_notes` when listing fails (and surfaces `FolderUnavailable`/`StorageError`). Covered by `SafNoteStoreTest` (fake SAF provider: null cursor throws, zero-row cursor lists empty, zero mtime sanitized, tmp created under the note's parent) and a `NoteRepositoryTest` case proving the list survives a transiently unreadable folder. `SafNoteStore` stays excluded from the Kover gate (device-only), but the new logic is now unit-tested through the fake provider.
