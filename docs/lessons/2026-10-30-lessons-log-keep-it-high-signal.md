# 2026-10-30 — Keep the lessons log high-signal: conditional rule enforced everywhere, index by topic, fold noise (issue #50 follow-ups)
- **Context:** Issue #50 changed the rule so a `docs/lessons/` entry is required only when a PR taught something non-obvious — but the old per-PR wording survived in `AGENTS.md` ("add a lesson after each merged task … do not skip") and `CONTRIBUTING.md`, so every PR kept adding lessons and the rule never took effect. A follow-up cleanup then deleted the checkbox-dump entries from the per-PR era, and unresolved PR #49 merge-conflict markers were still committed in `AGENTS.md` / `CONTRIBUTING.md` / `docs/WORKFLOW.md`. A final audit folded everything whose content is fully restated in `AGENTS.md` / `docs/ARCHITECTURE.md` / `docs/WORKFLOW.md` (quick-path rule, FileObserver-on-SAF, Kover gate, lint NewApi, Kotlin 2.0 plugin, persisted-permission check, swipe-background gating, resizable-widget handling, release-workflow setup, PR-template shape, and two earlier process notes).
- **Lesson:** Three meta-lessons. (1) When you change a rule, change **every** mention of it in the same PR — a rule softened in one place but left stale in another never takes effect; and never commit conflict markers in tracked docs. (2) A required-per-PR artifact becomes noise and buries the valuable entries — a high-signal log beats a complete one; when a rule changes, re-evaluate the artifacts produced under the old rule. (3) A log that grows linearly will eventually be unusable by humans and LLMs alike; the defenses are the non-obvious-only filter, a topic-grouped index with one-line takeaways, and periodic folding of anything fully restated in the canonical docs.
- **Rule now:** A lesson goes in `docs/lessons/` **only when non-obvious** (perf trap, API gotcha, CI failure, a decision you'd make differently); rule-changing PRs always get one; never one per PR to tick a box. The index in `docs/lessons/README.md` is grouped by topic, newest first per group; folded entries are marked `(folded)` and their content lives in `AGENTS.md` / `docs/ARCHITECTURE.md` / `docs/WORKFLOW.md`; once the log passes ~40 entries, fold or delete noise. All four canonical docs state the same conditional rule.
