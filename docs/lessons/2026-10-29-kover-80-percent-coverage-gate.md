# 2026-10-29 — Enforce 80% line+branch coverage with Kover instead of JaCoCo
- **Context:** Issue #3 asked for a required 80% coverage threshold (line and branch) wired into CI, with the repo starting above it.
- **Lesson:** Use Kover (`org.jetbrains.kotlinx.kover` 0.9.x), not JaCoCo, for Kotlin/AGP projects: it instruments on the fly during `testDebugUnitTest` (no separate exec files), understands Kotlin constructs (data classes, inline functions), supports AGP build variants (`koverVerifyDebug`), and fails the build via verify rules (`minBound(80)` / `minBound(80, CoverageUnit.BRANCH)`). Two gotchas hit along the way: (1) `InternalNoteStore.toFile` used `android.net.Uri`, whose methods are stubs that throw in local unit tests — switching to `java.net.URI` made the store unit-testable with zero behavior change; (2) `stateIn(WhileSubscribed)` never starts collecting without a subscriber, so ViewModel tests must attach a collector before asserting on `notes.value`. Device-only code (Compose screens, `MainActivity`, widget/tile, `SafNoteStore`) can't run on the JVM — exclude those classes from the gate in `app/build.gradle.kts` filters and cover them with instrumented tests instead, rather than chasing an unreachable 80% across the whole APK.
- **Rule now:** Every PR runs `./gradlew :app:koverVerifyDebug` locally and in CI (`pr.yml`); Kover rules require >= 80% line AND branch coverage of unit-testable code; coverage reports are uploaded as CI artifacts (`app/build/reports/kover/`). New testable logic must come with tests; new device-only code must be added to the Kover exclusion list with a reason.
