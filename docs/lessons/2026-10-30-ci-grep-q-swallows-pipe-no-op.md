# 2026-10-30 — `grep -q` in a pipeline is a no-op: never chain a second filter after it (issue #48)
- **Context:** Issue #48 — the `automated-review` job in `.github/workflows/pr.yml` scanned PR diffs for main-thread I/O with `git diff ... | grep -qE 'Dispatchers\\.Main' | grep -v 'withContext(...)'`. Two compounding bugs: (1) `grep -q` exits at the first match and prints nothing, so the downstream `grep -v` always received empty input and exited 1 — the whole pipeline could never fire, and every PR got "✅ No obvious main-thread I/O"; (2) in the YAML block scalar the pattern was written `Dispatchers\\.Main`, which under `grep -E` is a literal backslash followed by any char — it matched zero real lines anyway. A green check that guarantees nothing is worse than no check.
- **Lesson:** A pipeline's exit status is the *last* command's; `grep -q` anywhere mid-pipe makes every filter after it dead. To keep matches flowing and still exclude allowed lines, use `grep -E 'pattern' | grep -vq 'allowed'` (non-`-q` first stage, `-v -q` last stage so the status reflects "a non-excluded match exists"). And in YAML block scalars, write regex backslashes exactly as the shell should see them — `\.`, not `\\.` — then smoke-test the exact command against a violating line (old pipeline: exit 1 on `+val d = Dispatchers.Main`; fixed: exit 0).
- **Rule now:** `.github/workflows/pr.yml` `automated-review` now runs `git diff origin/main...HEAD -- '*.kt' ':(exclude)**/src/test/**' | grep -E 'Dispatchers\.Main' | grep -vq 'withContext(Dispatchers\.Main)'` (plus the `runBlocking|Thread\.sleep` clause, also test-excluded). Any future golden-rule grep added to CI must be smoke-tested with at least one violating and one allowed sample line before merge.
