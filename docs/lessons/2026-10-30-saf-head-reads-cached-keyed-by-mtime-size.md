# 2026-10-30 — SAF head reads must be cached keyed by (uri, lastModified, size); never per-refresh-per-note (issue #29)

- **Context:** Performance review (issue #29) found `listNotes()` on SAF folders opened one `openInputStream` Binder round-trip per note per refresh just to derive title/snippet, making every `onResume`/widget update hundreds of IPC calls on SD-card/cloud folders.
- **Lesson:** `NoteStore.listNotes()` returns metadata only (one `query()` with name/mtime/size in the projection); head-derived `title`/`snippet` are read separately via `store.readHead(uri)` and cached in the repository as `(uri, lastModified, size) -> (title, snippet)`. A refresh re-reads only files whose mtime/size changed since the last scan, and the cache is pruned to the listed keys each pass so folder switches and deleted files cannot leak stale entries. Per-save, `NoteRepository.writeNote` updates the edited entry in place (it is always the newest) instead of `map + sortedByDescending` over the whole list, and widget-refresh broadcasts are coalesced (2 s) instead of one rescan per debounced autosave. Filename timestamps switched from shared `SimpleDateFormat` to thread-safe `DateTimeFormatter` (concurrent `createNote` could corrupt names).
- **Rule now:** `NoteStore.listNotes()` never reads file contents; head reads go through `NoteStore.readHead()` and are cached by `(uri, lastModified, size)` in `NoteRepository`; the widget loader reads heads only for the top-N visible rows. Documented in `docs/ARCHITECTURE.md`.
