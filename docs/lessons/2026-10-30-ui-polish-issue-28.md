# 2026-10-30 — UI polish pass: strings, a11y, dark theme, swipe/search affordances (issue #28)
- **Context:** Issue #28 audited the three Compose screens plus widgets and listed presentational gaps: hardcoded English strings bypassing `strings.xml`, missing `contentDescription`s, a fixed light window theme, a search field with no visual affordance, a swipe background without a delete icon, and a widget with hardcoded colors and no ripple.
- **Lesson:** UI polish is cheapest when done as one resource-level pass — externalizing strings and adding content descriptions is compile-time only, and dark theme needs both the Compose `colorScheme` (`dynamic*ColorScheme` on S+ with a static fallback, gated on `isSystemInDarkTheme()`) *and* a `values-night` window theme, otherwise the status bar/window chrome stays light in dark mode. Compose `when` over a nullable enum state needs an explicit `null` branch to be exhaustive.
- **Rule now:** AGENTS.md already forbids hardcoded UI strings; this PR enforces it in practice (app title, back/search/delete descriptions, editor placeholder, saved indicator, settings row, tile label all come from `strings.xml`). Swipe-delete backgrounds must stay gated on `dismissDirection != Settled` (see 2026-10-29 lesson) and now use `errorContainer`/`onErrorContainer` with a delete icon for both swipe directions.
