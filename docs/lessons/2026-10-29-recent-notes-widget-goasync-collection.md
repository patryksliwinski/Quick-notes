# 2026-10-29 — Recent-notes widget: goAsync in onUpdate, fixed rows via pure mapping, package-scoped refresh broadcast

- **Context:** Issue #9 — home-screen widget listing the 5 most recent notes, each row opening that note in the editor.
- **Lesson:** A data-driven `AppWidgetProvider` must not scan the note store inside `onUpdate` on the main thread; use `goAsync()` + `WidgetNoteLoader` (`Dispatchers.IO`) and push the `RemoteViews` only after the load finishes. RemoteViews can't use Compose or a ListView adapter without a `RemoteViewsService`, so the simplest correct collection widget is a fixed 5-row layout whose rows are filled by a pure `widgetRows(notes, limit, emptyText)` mapping — that mapping (sort/limit/pad/empty-state) is what gets unit-tested. In-app changes reach the widget through an explicit `AppWidgetManager`-targeted `APPWIDGET_UPDATE` broadcast (package-scoped via `setPackage`) sent from `NoteRepository` after create/edit/delete; `updatePeriodMillis="0"` stays off because the app is the only writer.
- **Rule now:** `RecentNotesWidgetProvider.onReceive` handles the custom `ACTION_REFRESH` by re-running `onUpdate` for its own widget ids; `NoteRepository` broadcasts it after mutations; row mapping lives in `widgetRows` in `receiver/WidgetNoteLoader.kt` with tests in `RecentNotesTest`.
