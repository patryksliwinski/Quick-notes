# 2026-10-30 — Inbound quick capture: share target, static shortcut, duplicate (issue #31)

- **Context:** Issue #31 — add three inbound "always a new note" entry points: `ACTION_SEND` (text/plain, `EXTRA_STREAM` fallback) on `MainActivity`, a static `res/xml/shortcuts.xml` "New note" launcher shortcut, and a duplicate action in the editor overflow menu. Perf constraints from #29/#30: the quick path must stay pure (no dialogs, no blocking reads, no extra SAF round-trip before the editor is open).
- **Lesson:** The share-into-new-note path should reuse the exact optimistic-create + debounced-write flow as `ACTION_NEW_NOTE`: create an empty note via `NotesViewModel.createNote { }`, open the editor, then prefill through `EditorViewModel.open(meta, prefill)` → `onContentChange`, so the first `writeNote` happens via the existing 400 ms autosave. Do NOT pass the shared text into the create call together with an async `readNote` on open — the read can land after the prefill and clobber it with the still-empty file. Duplicate is a single `createNote(content)` write with a fresh `yyyyMMdd-HHmmss-<rand36>.md` name (the existing `newNoteFileName()` helper), not a read-modify-write of the original; the editor then switches to the new note. Intent-extra extraction (`EXTRA_TEXT` → `EXTRA_STREAM` fallback, scheme-checked) is pure logic and lives in `data/ShareIntentText.kt` so it is unit-testable without an Activity (MainActivity is excluded from the Kover gate).
- **Rule now:** Quick-capture entry points (share, shortcut, tile, widget, `+`) all funnel into `createNote` + editor open; prefill goes through the debounced autosave path only. `NoteStore` gained `createNoteWithContent(content)` (single write; `createNote()` delegates with `""`). Static shortcuts are declared in `res/xml/shortcuts.xml` + manifest meta-data only. All new user-visible strings live in `res/values/strings.xml`.
