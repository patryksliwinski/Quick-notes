# 2026-10-30 — One CI workflow per pipeline: never duplicate the Gradle build across workflows (issue #46)
- **Context:** Issue #46 — `ci.yml` and `pr-review.yml` both ran `testDebugUnitTest :app:koverVerifyDebug lintDebug assembleDebug` on every PR, so each push burned two full Android builds (~9 min wall time, duplicated failure noise). Worse, `pr-review.yml` piped the build output into `review-checks.log` and never uploaded it, so failures showed `exit code 1` with zero diagnostics.
- **Lesson:** Run the build exactly once per commit. If a second workflow needs the build's verdict, pass it via job status (`needs.<job>.result`) or a workflow output — never by re-running the tasks. Any step whose output is needed for debugging must stream to the job log or be uploaded as an artifact, not swallowed into a file.
- **Rule now:** `.github/workflows/pr.yml` (name `CI`) is the single pipeline: job `build-and-test` runs the four Gradle tasks on pushes to `main` and PRs; job `automated-review` (PR-only, `needs: build-and-test`) does the golden-rule grep, posts the review comment reporting `needs.build-and-test.result`, and requests the Copilot review — no SDK, no rebuild. `ci.yml` and `pr-review.yml` are deleted; `AGENTS.md`, `CONTRIBUTING.md`, `docs/WORKFLOW.md`, and the lessons index reference `pr.yml`.
