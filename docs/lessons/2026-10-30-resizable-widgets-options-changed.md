# 2026-10-30 — Resizable widgets: react to size via `onAppWidgetOptionsChanged`
- **Context:** issue #25 — home-screen widgets were constant-size (`resizeMode="none"` on the New-note widget, fixed 5-row layout on Recent notes) and did not react when the user resized them.
- **Lesson:** `resizeMode` alone only enables the launcher's resize handles; the provider must additionally override `AppWidgetProvider.onAppWidgetOptionsChanged` (system sends `ACTION_APPWIDGET_UPDATE_OPTIONS`) and re-render from the options bundle. `OPTION_APPWIDGET_MAX_HEIGHT` is in dp and is the current height; fall back to `minHeight` when absent (e.g. very old hosts). All dp→layout decisions (visible rows, subtitle visibility) live in one pure function (`widgetLayoutForHeight`) so they are unit-testable without a device; the receiver package stays excluded from the Kover gate.
- **Rule now:** resizable widgets must (1) set `android:resizeMode="horizontal|vertical"` + `targetCellWidth/Height` in the info XML, (2) override `onAppWidgetOptionsChanged` in the shared `BaseWidgetProvider` and re-run the per-id update, (3) derive all size-dependent layout from a pure, unit-tested function, and (4) make row containers `layout_height="0dp" + layout_weight="1"` with `GONE` for hidden rows so content stretches to fill the widget instead of leaving dead space.
