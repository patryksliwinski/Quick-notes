# 2026-10-30 — The "lesson only when non-obvious" rule was still not enforced; rule fixed everywhere and the log re-organized
- **Context:** Issue #50 changed the rule so a `docs/lessons/` entry is required only when a PR taught something non-obvious, but the old per-PR wording survived in `AGENTS.md` ("After each merged task, add a lesson file … **Do not skip this step.**") and in `CONTRIBUTING.md` ("Add a file under `docs/lessons/` in the same PR as the change"). So every PR kept adding a lesson anyway — the rule change never actually took effect. Unresolved merge conflicts from PR #49 were also left committed in `AGENTS.md`, `CONTRIBUTING.md`, and `docs/WORKFLOW.md`.
- **Lesson:** A rule that exists only in one place will be contradicted by the stale copy elsewhere — when you soften a rule, you must soften **every** mention of it in the same change, and never leave conflict markers in tracked docs. And a log that grows one entry per PR linearly will eventually be a mess no LLM (or human) can use; the only defense is the high-signal filter plus an index that stays findable at any size.
- **Rule now:** `AGENTS.md`, `CONTRIBUTING.md`, `docs/WORKFLOW.md`, and the `docs/lessons/README.md` index all state the same conditional rule: a lesson **only when non-obvious** (perf trap, API gotcha, CI failure, a decision you'd make differently); rule-changing PRs always get one; never one per PR to tick a box. The index in `docs/lessons/README.md` is grouped by topic (storage/SAF, app behavior, widgets, UI/list/editor, CI/release, process) with a one-line takeaway per row, and noise entries get folded or deleted once the log passes ~40 entries. Merge conflicts in `AGENTS.md` / `CONTRIBUTING.md` / `docs/WORKFLOW.md` resolved to the `pr.yml` side.
