# 2026-10-30 — Copilot review request never produced reviews; self-review must come after CI (issue #49)
- **Context:** Issue #49 — across all 25 closed PRs, the review workflow's step that calls `pulls.requestReviewers` with `copilot` never produced a single Copilot review (0 reviews on any PR). Meanwhile the agent's self-review comments were posted before CI finished, so merges happened on a head whose final CI run was never verified (on PR #45 both workflows failed *after* the previous PR had already merged on an unverified state). The `edited` trigger also re-ran the full Android build when only the PR title/description changed.
- **Lesson:** A review-request step that demonstrably never yields reviews is pure cost — remove it and document the outcome instead of keeping it "just in case". And a self-review posted before CI finishes attests to a build state that does not exist yet; the review loop must be ordered: open draft PR → wait for CI on the head (`gh pr checks --watch`) → self-review the diff *and* the CI/lint/coverage results → fix → re-run CI on the new head → merge only on the final head's green run. Title/description edits never change code, so the review workflow must not trigger on `edited`.
- **Rule now:** the `pr.yml` PR trigger is `opened`/`synchronize` only (no `edited`), and the Copilot `requestReviewers` step is removed from the `automated-review` job. `pull-requests: write` must stay on that job: the remaining "Post review comment" step writes comments on the PR via the issues API, which requires it (dropping it made the job fail with 403 "Resource not accessible by integration" — caught by CI on the first run of this change). The posted comment states the CI-first ordering. `docs/WORKFLOW.md`, `CONTRIBUTING.md`, and `AGENTS.md` describe the CI-first loop: self-review and merge only on the final head's green CI run, verified with `gh pr checks --watch`.
