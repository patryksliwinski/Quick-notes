# 2026-10-29/30 — Widget RemoteViews traps: off-main-thread loading, resize handling, layout weights (issues #9, #10, #14, #25, #34)
- **Context:** Five widget/list-layout bugs across the home-screen widgets: data loading inside `onUpdate` on the main thread (#9); copy-pasted widget plumbing before a shared base (#10); a red swipe background showing through settled rows (#14); widgets ignoring launcher resize (#25); and after making them resizable, widget rows collapsing to zero height so note content became invisible (#34).
- **Lesson:** (1) A data-driven `AppWidgetProvider` must never scan the note store in `onUpdate` on the main thread — use `goAsync()` + `Dispatchers.IO` via `WidgetNoteLoader` and push `RemoteViews` only after the load finishes; in-app mutations reach widgets through a package-scoped `APPWIDGET_UPDATE` broadcast (`setPackage`) from `NoteRepository`, coalesced, never per keystroke. RemoteViews can't use Compose or adapters, so the collection widget is a fixed row layout filled by a pure, unit-tested `widgetRows(notes, limit, emptyText)` mapping. (2) `resizeMode` alone only enables the launcher handles — the provider must also override `onAppWidgetOptionsChanged` and re-render; all dp→layout decisions (visible rows, subtitle) live in one pure `widgetLayoutForHeight()` function, and height must be read from both `OPTION_APPWIDGET_MAX_HEIGHT` and `MIN_HEIGHT` (`widgetHeightDp`) because hosts differ. (3) In a RemoteViews `LinearLayout`, `0dp`+`layout_weight` rows collapse to zero height when sibling rows are GONE on some launcher hosts — row containers stay `wrap_content`, every row slot is always bound, and hidden rows get their text cleared. (4) `SwipeToDismissBox` always composes `backgroundContent` behind transparent content, so the swipe background must be gated on `dismissDirection != Settled`, not assumed hidden when idle.
- **Rule now:** One abstract `BaseWidgetProvider` (RemoteViews + shared background + PendingIntents + AppWidgetManager push + resize re-render) means a new widget is exactly 4 steps: provider, layout, info XML, manifest receiver — the checklist lives in `docs/ARCHITECTURE.md` ("Adding a new widget"). Widget layout rules above are all encoded there; row mapping and dp→rows live in pure, unit-tested functions in `receiver/WidgetNoteLoader.kt`. Quick-add widgets keep golden rule #1 (`ACTION_NEW_NOTE`, always a new note).
