# 2026-10-30 — One-line notes must have an empty snippet; failed SAF head reads must not poison the head cache (issue #43)

- **Context:** Issue #43 reported two display bugs: (1) on internal storage a one-line note showed its title duplicated as the snippet, and (2) on a micro SD-card SAF folder the list showed the markdown file name instead of the note content.
- **Lesson:** `deriveSnippet()` must return `""` when the note has no body line distinct from the title — falling back to the (stripped) title line duplicates the title in the row, because `NotesListScreen.NoteRow` only hides the snippet when it is empty. Likewise, `NoteRepository.enrichHeads()` must never cache the file-name fallback produced when `readHead()` throws or returns empty (SD-card documents can report `lastModified`/`size` as 0 and transiently fail `openInputStream`); an uncacheable failure is re-derived on the next refresh, so the row recovers instead of sticking on the file name. `restoreNote()` must derive title/snippet from the restored content like every other create path.
- **Rule now:** `deriveSnippet(name, head)` = first non-blank line after the title line that differs from the stripped title, else `""`; `enrichHeads()` caches only successfully read non-empty heads keyed by `(uri, lastModified, size)`; all note-creation paths derive `HeadFields` from the written content.
