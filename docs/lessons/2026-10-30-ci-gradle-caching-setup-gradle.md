# 2026-10-30 — CI Gradle caching via `gradle/actions/setup-gradle` (issue #47)
- **Context:** Issue #47 — every CI run in `pr.yml` and `release.yml` downloaded the Gradle distribution and all dependencies and compiled from scratch (~4–5 min per run), because `actions/setup-java@v4` had no `cache:` and no `gradle/actions/setup-gradle` step existed. The build cache was already enabled (`org.gradle.caching=true` in `gradle.properties`), but nothing populated it across runners.
- **Lesson:** `gradle/actions/setup-gradle` is the single workflow-only change that caches both `~/.gradle/caches` (dependencies) and `~/.gradle/wrapper` (distribution) and validates the wrapper jar; combined with `org.gradle.caching=true` it also warms the Gradle build cache. It needs no project dependency and must run after `setup-java` and `checkout`.
- **Rule now:** Every Gradle build job in `.github/workflows/*.yml` (`pr.yml` `build-and-test`, `release.yml` `build-and-publish`) inserts `- uses: gradle/actions/setup-gradle@v4` immediately after `actions/setup-java@v4`, before the Android SDK setup.
