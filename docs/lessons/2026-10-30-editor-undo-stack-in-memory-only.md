# 2026-10-30 — Editor undo snapshots live in memory only; word count derives from the content flow (issue #32)
- **Context:** Feature B (#32) added an undo/redo stack, word count, insert timestamp, share/copy, and editor settings. The hard constraints came from #29/#30: no per-keystroke disk access, no main-thread I/O, leave-latency < 100 ms.
- **Lesson:** Undo history must never touch disk or a database — a capped in-memory `UndoStack` (≤50 snapshots, snapshots taken on each debounced save commit) gives correct undo/redo while keeping autosave a single SAF write per debounce window and `saveNow()` on back instant. Word/char count must be a pure `map` over the same `content` StateFlow the TextField already collects (no timer, no extra recomposition source), and `SharedPreferences` reads that can hit disk on first access must be wrapped in `Dispatchers.IO`, not called from composition.
- **Rule now:** Editor-derived state (undo stack, stats) is computed in memory from `content`; all settings reads that may touch disk run on `Dispatchers.IO`; settings writes use `apply()`. Strings stay in `strings.xml`; pure logic (`UndoStack`, `computeStats`/`appendTimestampLine`, `EditorPrefs`) lives in unit-testable classes with tests, keeping the Kover 80% gate green.
